# ダイエット継続アプリ 設計書（Claude Code用）

## 0. Claude Codeへの最初の指示

このファイルと `coach-system-prompt.md` を読んで、11章の順番どおりにアプリを作ってください。
- 方針：**完全無料**（すべて無料枠で動かす）
- 迷ったら「シンプル・無料・プライバシー優先」で判断する
- 各フェーズが終わったら、iPhoneのSafariで動作確認する手順を書いて止まる
- APIキーや秘密の値は絶対にフロントエンドのコードに書かない

---

## 1. アプリの概要

- **使う人**：本人（1人）とパートナー（1人、閲覧と応援だけ）
- **目的**：本人が「自分で決めたこと」を毎日続けられるように、AIコーチが伴走する
- **中心の機能**：AIコーチとのチャット（食べる前の相談・食べた後のリカバリー・ストッパー）
- **その他**：体重・食事写真・運動・生理周期・体調の記録、今日のやること、週のご褒美、イベントまでのカウントダウン、パートナーの応援

---

## 2. 技術構成（すべて無料枠）

| 部分 | 使うもの | メモ |
|---|---|---|
| フロントエンド | Next.js（App Router）+ TypeScript + Tailwind CSS | PWAとして作る |
| 公開 | Vercel（Hobbyプラン） | |
| DB・ログイン・写真保存 | Supabase（Freeプラン） | Postgres、Auth、Storage、Edge Functions |
| AIコーチ・写真分析 | Gemini API 無料枠（Flash系モデル） | 必ずSupabase Edge Function経由で呼ぶ |
| 通知 | Web Push（VAPID） | iOS 16.4以降、ホーム画面に追加した場合のみ |
| 定期実行 | Supabase の pg_cron | 通知の送信、データベースの定期アクセス |

- モデル名は固定で書かず、環境変数 `GEMINI_MODEL` で切り替えられるようにする（無料枠の対象モデルは変わることがあるため）
- iPhoneアプリ（App Store）にはしない（Appleの開発者登録が有料のため）

## 3. プライバシー方針（方式B：無料枠＋送る情報を減らす）

Gemini APIの無料枠は、送った内容が製品改善に使われ、人間が読む可能性がある。そのため **AIに送る情報を最小限にする**。

### AIに送らないもの
- 本名 → アプリ内の**ニックネーム**（本名以外）だけを使う
- パートナーの名前 → 「パートナー」とだけ送る
- 住所、勤務先名、学校名、イベントの具体的な場所
- 顔や体が写った写真
- 写真の位置情報・撮影日時（EXIF）

### AIに送るもの（必要最小限）
- ニックネーム、身長、目標体重、体質メモ
- 体重（今朝・7日平均）、周期の時期（例：「生理前」）
- 今日食べたもの・運動・やること・体調
- 直近のチャット（最大20往復まで）
- 料理だけを切り抜いた写真

### 実装ルール
- 写真は送信前に**端末側で**：
  1. 料理部分を切り抜く画面を必ず通す
  2. 長辺1024px以下に縮小、JPEGに変換
  3. Canvasで描き直してEXIFを消す
- 体の写真（進捗写真）機能は作る場合も **Supabaseに保存するだけで、AIには絶対に送らない**
- イベントは「11/8 大切な人に会う日」のようにタイトルだけ送る。場所は送らない
- 本人がチャットに本名などを書いた場合に備え、送信前に「プロフィールの本名」「パートナーの名前」を文字列置換で伏せる（本名とパートナー名は端末のローカル設定にだけ保存し、DBにもAIにも送らない）
- **初回起動時に同意画面**を出す：
  - AIコーチは無料枠のAIで動いていて、送った内容がGoogleの製品改善に使われ、人が読む可能性があること
  - 本名・顔写真は送らない仕組みになっていること
  - 同意しない場合、AIコーチ機能だけオフで記録機能は使えること

## 3.5 送信前チェック（プライバシーガード）

AIに送る直前に、**端末の中だけで**内容をチェックする。チェックのために外部へデータを送らない。
この仕組みは「その人が誰か分かる情報」を止めるためのもの。体重や食事など、コーチに必要な情報は対象外。

### 判定の3段階
| 判定 | 動き |
|---|---|
| **ブロック** | 送信できない。理由を表示して、修正をうながす |
| **自動で伏せる** | 該当部分を「＊＊＊」に置き換えて送る。送る前に置き換え後の文を見せる |
| **確認** | 「この内容を送っても大丈夫？」と表示し、本人が選ぶ |

### 文章のチェック（正規表現＋ローカル辞書）
| 対象 | 判定 |
|---|---|
| 本名、パートナーの名前（端末のローカル設定に登録） | 自動で伏せる |
| 「伏せたい言葉」リスト（勤務先・学校・友達の名前など、本人が端末に登録） | 自動で伏せる |
| 電話番号、メールアドレス、郵便番号 | ブロック |
| 住所らしい文字列（都道府県・市区町村＋番地） | ブロック |
| クレジットカード番号、マイナンバーらしい数字の並び | ブロック |
| URL、SNSのアカウント名（@から始まる文字列） | 確認 |

- ローカル辞書は端末の中（localStorage／IndexedDB）にだけ保存し、DBにもAIにも送らない
- 設定画面に「伏せたい言葉」の追加・削除画面を作る

### 写真のチェック（ブラウザ内で動く無料のモデル）
| 対象 | 方法 | 判定 |
|---|---|---|
| 人の顔 | MediaPipe Face Detector（ブラウザ内） | ブロック |
| 人の体 | MediaPipe Object Detector の「person」 | ブロック |
| 写真の中の文字（レシート、名札、画面のスクショ、書類） | 文字認識（任意。重い場合は後回し） | 確認 |
| 位置情報・撮影日時（EXIF） | Canvasで描き直して削除 | 常に削除 |

- ブロックされた写真は、AIには送らない。食事記録としてSupabaseに保存するかは本人が選べる
- 切り抜き画面で料理部分だけにすれば送れる、と案内する

### 限界（本人にも設定画面で説明する）
- 自動チェックは完璧ではない。横顔、手書きの名前、辞書にない固有名詞などは見逃すことがある
- 逆に、料理の写真を人と判定するなど、送れるものを止めることもある。その時は切り抜き直しで対応
- 体重・生理周期・気持ちの相談など、コーチに必要な健康情報はチェックの対象外（送らないとコーチが機能しないため）。これは初回の同意画面で説明済み

## 4. ユーザーと権限

| 役割 | できること |
|---|---|
| 本人（owner） | すべての記録・コーチチャット・設定 |
| パートナー（partner） | 本人が共有を許可した項目の閲覧、応援メッセージの送信 |

- 招待コードで本人とパートナーをつなぐ
- **コーチとのチャットはパートナーには見えない**（設定でも変えられない）
- 共有設定（本人が切り替え）：
  - 体重：見せない ／ 7日平均だけ ／ 毎日の数字も
  - 食事写真：見せる ／ 見せない
  - 生理周期：見せる ／ 見せない
- すべてのテーブルにSupabaseのRow Level Security（RLS）を設定し、上の権限をDB側で守る

## 5. 画面一覧

### 本人側
1. **初回設定**：同意画面 → ニックネーム（初期値：「なすび」。コーチは「なすびさん」と呼ぶ）→ 身長・目標体重（下限46kg、これより低い値は入力不可）→ 体質メモ → 周期（前回の開始日・平均周期）→ ホーム画面に追加の案内 → 通知の許可
2. **ホーム**
   - コーチの今日の一言
   - 今日やること（最大3つ、チェックできる）
   - 連続記録日数、週のご褒美までの残り日数
   - 次のイベントまでのカウントダウン
   - パートナーからの応援（届いていれば）
   - 大きなボタン：「食べる前に相談」「記録する」
3. **コーチチャット**：テキスト＋写真。返事待ちの間は「考え中…」表示
4. **記録**：体重 ／ 食事（写真・メモ・時刻）／ 運動（種類・時間）／ 体調（熱・お腹・だるさ・メモ）／ 生理（開始・終了）
5. **グラフ**：体重（毎日の点＋7日平均の線、主役は線）、続いた日数、相談できた回数
6. **ご褒美**：今週のご褒美を設定（例：新しい服を1つ）、達成条件（記録できた日数）、週1回の「お休み券」
7. **予定**：バイトなどの予定（コーチと通知が使う）、イベント
8. **設定**：共有範囲、通知の時間、ニックネーム、データの書き出し・削除

### パートナー側
1. **応援ホーム**：連続記録、今日のやることの達成状況、ご褒美までの残り、カウントダウン、共有された項目
2. **応援を送る**：スタンプ＋ひとこと（本人のホームとコーチの振り返りに出る）

## 6. データ構造（Supabase / Postgres）

```
profiles
  id (uuid, auth.users), role ('owner'|'partner'), nickname, height_cm,
  target_weight_kg (>=46), body_notes, consent_ai (bool), created_at

pairs
  owner_id, partner_id, invite_code, created_at

share_settings
  owner_id, weight_mode ('none'|'avg'|'daily'), share_meal_photos (bool), share_cycle (bool)

weights
  id, owner_id, date, weight_kg, body_fat_pct (nullable, 参考値)

meals
  id, owner_id, eaten_at, note, photo_path (nullable), ai_analysis (jsonb, nullable),
  asked_before (bool)  -- 食べる前に相談したか

exercises
  id, owner_id, date, kind, minutes, note

conditions
  id, owner_id, date, fever_c (nullable), stomach, fatigue, note

cycles
  id, owner_id, start_date, end_date (nullable)

todos
  id, owner_id, date, text, done (bool), source ('coach'|'self')

schedules
  id, owner_id, starts_at, ends_at, kind ('work'|'pilates'|'other'), title

events
  id, owner_id, date, title   -- 場所は持たない

rewards
  id, owner_id, week_start, title, required_days, used_rest_pass (bool), achieved_at (nullable)

chat_messages
  id, owner_id, role ('user'|'coach'), text, photo_path (nullable), created_at
  -- RLS：ownerのみ。partnerは読めない

cheers
  id, owner_id, from_partner_id, stamp, text, created_at, shown_to_coach (bool)

push_subscriptions
  id, user_id, endpoint, keys (jsonb), created_at
```

- 写真はStorageの非公開バケットに保存し、署名付きURLで表示する
- 7日平均・連続日数・周期の時期はSQLのビューまたは関数で計算する

## 7. AIコーチの処理

Supabase Edge Function `coach-reply`：

1. ログイン中のユーザーが owner で、`consent_ai = true` か確認
2. DBから今日の状況を集める（`coach-system-prompt.md` の4章の項目）
3. 3章のルールで伏せ字・最小化をする
4. `coach-system-prompt.md` の `{{ }}` を埋めて、システムプロンプトとして送る
5. 直近20往復のチャット＋今回のメッセージ（＋処理済みの写真）を送る
6. 返事を `chat_messages` に保存して返す

**エラー時**
- 429（回数制限）の時は、自動で少し待って1回だけ再試行。それでもだめなら「今AIが混んでいるので、数分後にもう一度送ってね。記録はちゃんと保存されてるよ」と表示し、メッセージは保存しておく
- AIが使えない時もアプリの記録機能は全部動くようにする

**写真分析**（Edge Function `analyze-meal`）
- JSONで返させる：`{ carbs: 'low'|'mid'|'high', fat: ..., protein: ..., vegetables: ..., processed_food: bool, gut_friendly: 'more'|'less', comment: '一言' }`
- カロリーの数字は出さない（写真からの推定は誤差が大きいため）。必要なら「軽め／ふつう／しっかり」の3段階

## 8. 通知

pg_cron で定期的に Edge Function `send-push` を呼ぶ。

| タイミング | 内容 |
|---|---|
| 朝（設定時刻） | 「おはよう。体重と今日やることを決めよう」 |
| バイト終了時刻 | 「お疲れさま。帰ったら最初に◯◯を食べよう」（コーチの定型文から選ぶ。AIは呼ばない） |
| 夜（設定時刻） | 「今日の振り返りをしよう」 |
| パートナーの応援が届いた時 | 「応援が届いてるよ」 |

- 通知文はAIを呼ばずテンプレートから作る（無料枠の回数を節約するため）
- iOSの通知は止まることがあるので、アプリを開いた時にもホームに同じ内容を出す

## 9. 無料枠の限界と対策

| 限界 | 対策 |
|---|---|
| Gemini無料枠の回数制限・予告なしの変更 | 再試行1回＋丁寧なエラー表示。通知文はAIを使わない。チャット履歴は20往復まで |
| Supabaseは7日間使われないと一時停止 | pg_cronで毎日DBに軽くアクセスする。止まっても90日以内なら管理画面から復旧できる |
| 写真の保存容量（無料枠） | 送信前に圧縮。古い写真は90日後に自動で縮小版だけ残す |
| iOSの通知はホーム画面追加が必須 | 初回設定で追加方法を画像つきで案内。ブラウザで開いている時は案内バナーを出す |

---

## 10. 守ること（コーチ以外の部分も）

- 目標体重は46kg未満を入力できない
- 体重のグラフは7日平均の線を主役に、毎日の点は薄く表示
- 「食べすぎ」「失敗」などの赤い警告表示を使わない
- 記録が途切れても責める表示を出さない（「おかえり」で迎える）
- 体調の記録で発熱などがある日は、ホームの「今日やること」を自動で「休む」に切り替える
